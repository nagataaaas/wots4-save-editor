# 武器レコード

帯刀中・武器袋・武器箪笥の武器。1件 0xA0 バイトの固定長レコードで、3つの範囲が同じ構造を使う。

## 範囲

| 項目 | 値 | 確度 |
|---|---|---|
| 開始 | `0x00A4C8` | ✅位置 ／ 🟢境界 |
| 終了（含む） | `0x0129F6`（武器箪笥の本数と容量を含む） | 🟢 |
| サイズ | 0xA0 × 213件と、その間の帯刀の状態 8 B・隙間 4 B、末尾の本数と容量 3 B | 🟢 |
| 位置の求め方 | 固定オフセット（U-1 判定待ち）。アンカー探索の目安は、0xA0 周期で攻撃力・耐久・魅力が妥当な値のレコードが続く場所 | ✅位置 ／ ❓探索（[U-1](../../../check-diff.md#u-1)） |
| 妥当性検証 | 全レコードで攻撃力 ≤ 500、耐久 ≤ 2000、魅力の個数合計 ≤ 3 | ✅ |

```text
帯刀中[n]   = 0xA4C8 + n * 0xA0   （n = 0〜2）
帯刀の状態  = 0xA6A8〜0xA6AF
武器袋[n]   = 0xA6B0 + n * 0xA0   （n = 0〜9）
隙間        = 0xACF0〜0xACF3
武器箪笥[n] = 0xACF4 + n * 0xA0   （n = 0〜199）
本数と容量  = 0x129F4〜0x129F6
```

- 🟢 レコードは完成武器ID から始まる 0xA0 B。[TS] はレコードの先頭を 6 B 前（`0xA4C2`・`0xA6AA`・`0xACEE`）に置いていて、[TS] の配置での位置は下の表の位置 + 0x06（表の [TS] の列）。check-diff の U-n の位置は [TS] の配置で書いている
- 帯刀中と武器袋の間の 0xA6A8〜0xA6AF は帯刀の状態（[belt-state](../belt-state/README.md)）。どのレコードとも重ならない 🟢
- 🟢 武器箪笥の200件分の領域は、解放の段階にかかわらず常にある。使えるのは先頭から「容量」件（下の「武器箪笥の本数と容量」）
- 🟢 空きのレコードは、刃・X・鍔・柄の4つがすべて `0xFFFF` のもの（ほかのバイトは 0）。ゲームは空きのレコードから武器を作らない
- 帯刀中の3件と同じ並びが [belt-copy](../belt-copy/README.md)（俺流の技の表）の後半に見えることがある。ゲームの状態ではない値で、帯刀の武器はそこからは読まれない 🟢

### パーツ（+0x02〜+0x09）

- 2 B × 4（刃・X・鍔・柄、各 u16 LE）として読み書きする ✅（[U-3](../../../check-diff.md#u-3)）
- X は鞘の ID で、刃によって決まる ✅。見た目の鞘が同じ武器どうしで同じ値になる。刃の ID からの規則で計算できない刃がある（規則と例外は blade.csv の `sheath_x` と備考）
- 特殊武器の刃は X が `0xFFFF`（刃の下位16ビットが ID）✅。特殊武器には鞘・鍔・柄の部品がなく、X・鍔・柄はすべて `0xFFFF` ✅
- 🟢 鍔が `0xFFFF` の武器が特殊武器として扱われる
- 書き込みは刃 ID と X を組で書き、鍔・柄は ID だけを書く
- [TS] の 3 B 値（刃 3 B＋鍔 3 B＋柄 2 B）で書くと X の一部だけが書き換わるので使わない。既知パーツを揃えて書いたバイト列は [TS] の 3 B 値と同じになる
- ID 空間・並びの規則・未登録パーツは [datatable/README.md](../../datatable/README.md)

### 魅力（+0x1E）

1組 4 B（魅力ID u16＋個数 u16）× 3組 ✅。魅力ID は [魅力](../../datatable/weapon/charm.csv)。

| 位置（+0x1E から） | 型 | 内容 |
|---|---|---|
| +0 / +2 | u16 / u16 | 1つ目の魅力ID / 個数 |
| +4 / +6 | u16 / u16 | 2つ目の魅力ID / 個数 |
| +8 / +10 | u16 / u16 | 3つ目の魅力ID / 個数 |

- 空いている組は `FF FF 00 00`
- 組の並び順は自由
- 読み出し：同じIDが2組に分かれた形も受け付ける
- 書き込み：同じIDを1組にまとめて個数で表し、使う組を前に詰める（例：重撃×2・活復×1 → `09 00 02 00 | 04 00 01 00 | FF FF 00 00`）

### 銘（+0x90）

- 形式：`<銘ID下位> 01 <番号>`。銘ID＝0x016A＋番号（u16 LE）✅
- 銘なしは `FF FF FF`
- 値は [銘](../../datatable/weapon/title.csv) の `save_bytes_le`
- 🟢 番号 5〜9（石頭・鉄壁・白金造・金剛造・不壊）は耐久の減り方を変える

### 固有武器の6バイト

固有武器（流派の秘伝を持つ武器）の +0x0A〜+0x0F にあるバイト列。位置・バイト列は ✅（[U-9](../../../check-diff.md#u-9)）。
完成武器ごとの値は complete.csv の `unique_bytes`（空欄は固有武器でない）。

### 値の範囲

| 項目 | ゲーム上の範囲 | 型で書ける範囲 |
|---|---|---|
| 攻撃力 | 最大500。銘を付けても500を超えない | i16 |
| 耐久（現在・最大） | 最大2000 | i16 |
| 質（現在・最大） | 武器ごとに異なり、最大21 | i16 |
| 魅力 | 個数の合計が最大3 | — |
| 斬殺数 | 4万を超えると表示が崩れるという報告あり | u16 |

- 🟢 読み込み時にも保存時にも、攻撃力・耐久・質・魅力の個数の範囲は検査されない。書いた値がそのまま使われる（範囲外の値でゲームが正しく動くかは別。要ゲーム内確認）

### 鍛冶屋の精錬で変わる値 🟢

「精錬したい」の3つの選び方で、レコードの値は次のように変わる。q は精錬する前の質（+0x14）。

| 選び方 | できない条件 | 変わる値 |
|---|---|---|
| 強くしたい | 折れている、攻撃力 ≥ 500、q ≥ 質の最大 | 攻撃力 += 上昇（1〜500 に収める）、質 = q + 1 |
| 硬くしたい | 折れている、最大耐久 ≥ 2000、q ≥ 質の最大 | 最大耐久 += 500（100〜2000 に収める）、質 = q + 1 |
| 磨いてほしい | 現在の耐久 ≥ 最大耐久 | +0x88 += 最大耐久 − 現在の耐久（999999 まで）、現在の耐久 = 最大耐久、折れた状態を消す |

- 新しく作られた武器の質は 1（一度も精錬していない武器は 1）。質 0 は通常のプレイでは現れない
- 精錬できる回数は「強く」「硬く」を合わせて 質の最大 − 質 回まで（新しい武器なら 質の最大 − 1 回）。質は 999 で止まる
- 攻撃力の上昇 ＝ (q + 1) ＋ 乱数。乱数の幅は q で変わる

  | q | 乱数 | 上昇 | 上昇の最大 |
  |---|---|---|---|
  | 1〜5 | 5〜10 | q + 6 〜 q + 11 | 16（q ＝ 5） |
  | 6〜20 | 1〜20 | q + 2 〜 q + 21 | 41（q ＝ 20） |
  | 21 以上 | 0 | q + 1 | — |

- 鍛冶屋の主が堂島のときは、上昇にさらに +1 か +2（半々）。q ＝ 20 の最大は 43
- 質の最大 21 の新しい武器（質 1）を 20 回「強く」したときの上昇の合計は 270〜580（攻撃力は 500 で止まる）
- 質の最大より質が大きい武器もある（実セーブに質 24・質の最大 16 の武器）。精錬では質の最大を超えないので、ほかの場面で増えたもの（流通の記録の精錬は質の最大を見ない 🟢）
- 料金：強く ＝ 1000 × q、硬く ＝ 2000 × q、磨く ＝ 100 両。`0x14066`（u8、0〜6 の段階 🔶）が 5 以上なら強く・硬くは ×0.6。
  さらに治安（`0x0015`）で 90 以上 ×0.5、70〜89 ×0.7、30〜69 ×1、10〜29 ×1.3、10 未満 ×1.5。`0x375D`（病院の開閉）が 0 でなければ 1 割増し
- 要ゲーム内確認（精錬の前後の実セーブはまだない）

### 名前（+0x2A・+0x6C）🟢

- +0x6C（i32）が 0 以上なら、その番号の完成武器の名前が表示され、+0x2A の文字列は使われない。−1 のときだけ +0x2A の文字列が使われる
- 「完成武器の名前を書き換えても元に戻る」報告はこのため。完成武器に好きな名前を付けるには、+0x6C〜+0x6F を `FF FF FF FF` にして +0x2A に名前を書く（ほかの表示・動作への影響は要ゲーム内確認）
- +0x93 が 1 以上なら、どちらの場合も「*****」と表示される

### 武器箪笥の本数と容量（武器箪笥の直後）🟢

| 位置 | 幅 | 型 | 内容 | 値 |
|---|---|---|---|---|
| `0x129F4` | 2 B | i16 | 武器箪笥に入っている武器の本数 | 実セーブで 36 |
| `0x129F6` | 1 B | i8 | 武器箪笥の容量 ÷ 10 | 新しく始めたとき 2（20本）、上限 20（200本）。実セーブで 14 |

- 武器を箪笥に入れるときは、先頭から「容量」件の中の空きを探す。本数が容量以上なら入れられない
- 箪笥の中のレコードを書き換えて武器を増やす・減らすときは、本数も合わせる必要があるとみられる 🔶（要ゲーム内確認）

## 編集時の注意

- 通常モードはゲーム上の範囲で拒否し、上級者モードのときだけ型で書ける範囲まで許可する。現在の質だけは上限を設けない（ユーザー判断 2026-10-08）
- 魅力の個数の合計は3以下（4以上で箪笥を開けなくなった報告あり）
- 武器名は17文字まで（[U-5](../../../check-diff.md#u-5)）。UTF-16LE の固定長フィールドを上書きする
- レコードを丸ごとコピーするときは、+0x00〜+0x9F（完成武器ID から）を単位にする 🟢
- 武器種は上級者モードでだけ変更できる。パーツと合わない武器種にしたときの動作は ❓
- 銘「人斬り」は `6A 01 00`。[TS] の定義値 `00 6A 01` は未知の銘として扱う（[U-2](../../../check-diff.md#u-2)）
- 完成武器のデフォルト名を書き換えても、帯刀すると元に戻るという報告がある（Wiki）。理由は上の「名前」🟢
- 完成武器に変更するときは、+0x00〜+0x0F・+0x18・+0x1A・+0x1C・+0x6C〜+0x6F をその完成武器の値（complete.csv）にそろえる。
  攻撃力・耐久・質・魅力・名前・銘などは変えない
- 武器箪笥の容量は、武器が入っている枠と本数が収まる値（20〜200本）だけにする 🟢
