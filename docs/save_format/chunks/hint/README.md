# 次のイベントのヒント

ゲーム内の「港の様子でも見てみるか」のような、次のイベントのヒント。
セーブにはヒントの文そのものではなく、**最後に進めたイベントのチャート上のノード番号**が入り、ゲームはこの番号から文を決める。

## 範囲

| 項目 | 値 | 確度 |
|---|---|---|
| 開始 | `0x003900` | ✅ |
| 終了（含む） | `0x003901` | 🔶 |
| サイズ | 2 B | 🔶 |
| 位置の求め方 | 固定 | ✅ |
| 妥当性検証 | 0〜118（[チャートのノード](../../datatable/event/chart-node.csv)）または `0xFFFF` | 🟢 |

## 構造

| 位置 | 幅 | 型 | 内容 | 値 | 確度 |
|---|---|---|---|---|---|
| `0x3900` | 2 B | u16 | 最後に状態を進めたイベントの、チャート上のノード番号。書き換えるとヒントの文が変わる | 0〜118（[chart-node.csv](../../datatable/event/chart-node.csv)）。`0xFFFF`＝なし（🔶） | ✅ 位置 ／ 🟢 値の意味 |

### ノード番号

- イベントチャートの枠ごとに振られた 0〜118 の番号で、イベントの通し番号（[event-chart](../event-chart/README.md)）とは別（🟢）
- 1つのイベントが複数の枠を持つことがある（大老暗殺計画は段階ごとに7つ、大老 鬼怒川怨仙は4つ、小公女倒れるは3つ）。イベントに当たらないノード（0・1・53・113・114・118）もある（🟢）
- 対応表：[datatable/event/chart-node.csv](../../datatable/event/chart-node.csv)

|---|---|---|
| 2 | 志士との出会い | 志士との出会いの導入 |
| 3 | 代官所の面々 | 代官所の面々の完了 |
| 5 | 海兵隊の横暴 | 海兵隊の横暴の完了 |
| 6 | 琴吹光探検隊 | 琴吹光探検隊の完了 |
| 8 | 代官所潜入 | 代官所潜入の完了 |

| 10 | 辻斬りを辻斬る | 辻斬りを辻斬るの完了 |
| 78 | 船上の侍 | 阿弥浜港争乱をスキップした直後 |

### ヒントの文

ヒントの文はノードごとに1つ決まっている（🟢）。文は約90種で、「さて どうしたものか」が既定の文（ヒントなし）。

1日目のノードの文（🔶。6 だけはゲーム内で確認済み ✅）：

| ノード | イベント | ヒントの文 | 次に起こせるイベント（参考） |
|---|---|---|---|
| 2 | 志士との出会い | さて どうしたものか | — |
| 3 | 代官所の面々 | 大通りの様子を見に行くか | |
| 4 | 小公女謁見 | 領事館の様子を見てみるか | |
| 5 | 海兵隊の横暴 | 夕方 朱美の店に行ってみるか | |
| 6 | 琴吹光探検隊 | 港の様子でも見てみるか | 阿片密売を阻止せよ（港の警備） |
| 7 | 電信あり | 夜の領事館の様子でも見てみるか | 辻斬りを辻斬る |
| 8 | 代官所潜入 | 神社の様子でも見に行ってみるか | 欺きの代価 |
| 9 | 阿片密売を阻止せよ | 三姉妹は元気にしているだろうか | 西洋医学お断り（三姉妹の依頼） |
| 10 | 辻斬りを辻斬る | ローラは元気にしているだろうか | 病院占拠事件（ローラの依頼） |

2日目以降のノードと文の対応は ❓。
3日目以降のノードでは、上の表と同じ並びの続きとしては説明できない。たとえば 78（船上の侍）を書き込むと「何やら騒がしいな」になった。

### 文が出ないとき

- ノードに文があっても、既定の「さて どうしたものか」になることがある。2日目昼のセーブに 7・13・18・83・89 を書き込むと、どれも既定の文になった（✅）
- 🔶 ヒントの文は、そのノードの次の時間帯にだけ出る。7（電信あり → 夜の領事館）は1日目夜向けの文なので、2日目昼では出ないと考えられる
- 「さて どうしたものか」そのものを持つノードもある（2 志士との出会い など）

## 編集時の注意

- 書く値は [chart-node.csv](../../datatable/event/chart-node.csv) の ID（0〜118）か `0xFFFF` に限る
- ノードの時間帯と現在の時間帯が合わないと、既定の文になる（🔶）。ヒントを変えたいときは、現在の時間帯の直前に当たるノードを選ぶ

## 未確認・判定待ち

- ❓ 2日目以降のノードの文。同じ時間帯のセーブに、その直前の時間帯のノードを書き込んで確かめる
- ❓ 文を出す条件。時間帯だけで決まるのか、次のイベントの状態（済み・受けられるか）も見るのか
- ❓ `0x3901` が上位バイト以外の意味を持つか（`0xFFFF` のとき以外は 0）
