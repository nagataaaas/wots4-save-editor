# 次のイベントのヒント

ゲーム内の「どこどこに行ってみるか」のような、次のイベントのヒントの番号。

## 範囲

| 項目 | 値 | 確度 |
|---|---|---|
| 開始 | `0x003900` | ✅ |
| 終了（含む） | `0x003901` | 🔶 |
| サイズ | 2 B | 🔶 |
| 位置の求め方 | 固定（U-1） | ❓ |
| 妥当性検証 | 実データで見た値（2, 3, 5, 6, 8, 9, 10, 78, 83, 86, 88, 89, `0xFFFF`） | 🔶 |

## 構造

| 位置 | 幅 | 型 | 内容 | 値 | 確度 |
|---|---|---|---|---|---|
| `0x3900` | 2 B | u16 | ヒントの番号。書き換えるとヒントの文が変わる | `0xFFFF`＝ヒントなし（🔶）。番号と文の対応は下の表 | ✅ 位置 ／ ❓ 番号の意味 |

### 番号と文の対応

2日目昼のセーブで書き換えて確かめた値：

| 値 | ヒントの文 |
|---|---|
| 6 | 港の様子でも見てみるか |
| 7・13・18・83・89 | さて　どうしたものか（ヒントなし） |
| 78 | 何やら騒がしいな |

- 番号はイベントの添字とは別の表と考えられる（🔶）。多くの番号は文を持たないか、出せる時期（日・時間帯）や条件が合わないと既定の文になる
- 実データでは「値＋4＝ヒントのイベントの添字」となる例があるが、合わない値も多い

## 編集時の注意

- 番号と文の対応が分かるまで、生の値として扱う

## 未確認・判定待ち

- ❓ `0x3901` が上位バイト以外の意味を持つか（`0xFFFF` のとき以外は 0）
