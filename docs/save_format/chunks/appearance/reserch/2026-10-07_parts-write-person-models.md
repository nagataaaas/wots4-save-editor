# 人物の番号を FFFF にした書き込みと、部品の組のモデルの値

- 日付：2026-10-07
- 目的：[1回目の書き込み](2026-10-07_parts-write-face-hair.md)で顔・髪型が反映されなかった原因を調べる。髪型の解放ビットを確かめる（U-19）
- 環境：Steam版、ファイルサイズ `0x48BB0`。容姿「幕末の志士」の実セーブのコピー

## 書き込みの確認

いずれも顔 `0x3AAFC` を `00 00`（青年主人公）、髪型 `0x3AB08` を `0D 00`（アフロ）にしたうえで行った。

| 試行 | 追加の書き込み | 結果 [U] |
|---|---|---|
| (a) | `0x3AAD4` `EE 00` → `FF FF`、`0x3AAD6` `FF FF` → `EE 00` | 顔・髪型が反映された。ただし髪型はポリゴンの向きがばらばらで頭皮が見え、粗いモデルのような見た目 |
| (b) | 写しの顔 `0x3AC94`・`0x3DBB0` を `00 00`、髪型 `0x3ACA0`・`0x3DBBC` を `0D 00` | 変わらなかった |

髪型の解放：`0x3AB6A` を `00` → `FF` にすると、髪型の一覧に服の番号 112〜119 の髪型（後ろ結び2・撫で付け・アフロ・七三・ヤクザ・角刈り・外国人男性の髪型・海兵隊の髪型）が出た ✅ [U]。

## サンプル

| ファイル | 操作 |
|---|---|
| 実セーブ（前） | 幕末の志士を選んだ直後。データの操作なし |
| 実セーブ（後） | 1回目と同じ顔・髪型の書き換えをしてロードし、ゲーム内で下半身だけを変えて保存 |

## 差分（前 → 後、見た目のレコード）

| 位置 | 前 → 後 | 解釈 |
|---|---|---|
| `0x3AAD4` u16 | 238 → `FFFF` | 部品を変えると人物の番号が `FFFF` になる |
| `0x3AAD6` u16 | `FFFF` のまま | |
| `0x3AAF0`〜`0x3AAFB`（下半身の組） | 95, 0, 213, 279, 213, −1 → 88, 0, 196, 255, −1, −1 | 下半身 95 → 88 |
| `0x3AAFC`・`0x3AB08`（顔・髪型） | 43・42 のまま | ロード時に書き換えが捨てられ、幕末の志士の部品で保存された |
| `0x3AAE6`・`0x3AB0A`・`0x3AB3A`・`0x3AB46`（組の2つ目） | 変化 | 部品の選択と関係なく変わる ❓ |

写し（`0x3AC6C`・`0x3DB88`）は変わらなかった。ほかの差分は帯刀武器とその写しの範囲。

## 部品の組の3〜6つ目の値

部品の組 `+4`〜`+B` の u16 × 4 は、部品ごとに決まった「モデルの値」🟢。部品が使う最大4つのモデルの値で、使わない枠は −1。
観測した7組（上半身 70、下半身 95・88、顔 43、髪型 42、k＝4 の 7、足元 33）がすべて計算と一致した。
部品ごとの値は datatable の `save_models` 列に入れた。

(a) の髪型が崩れたのは、髪型の番号だけを 13（アフロ、モデルの値 `66, −1, 60, −1`）にして、モデルの値を幕末の志士の髪型（`82, −1, 60, −1`）のまま残したため、とみられる。

## 結論

- 人物の番号 `0x3AAD4` が人物を指していると、ロード時に部品はその人物から作り直される。部品を書くときは `0x3AAD4` を `FFFF` にする（🟢 差分と (a) の結果から）
- 部品の番号と一緒に、その部品のモデルの値（`save_models`）も書く必要がある 🔶（モデルの値も合わせて書いた確認はまだ）
- 写しは見た目に使われない（(b)）
- 髪型も服のビット列で解放する ✅（112〜119）
- `0x3AAD6` を `EE 00` にしたことの影響は ❓（ゲーム内で下半身を変えたセーブでは `FFFF` のまま）
