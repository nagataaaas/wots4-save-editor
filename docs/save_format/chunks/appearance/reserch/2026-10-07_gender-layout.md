# 体型・身長の反映確認と性別変更後の並び

- 日付：2026-10-07
- 目的：体型・身長の確度を更新し、性別変更後に見た目の候補が読めない原因を特定する
- 環境：Steam版、各セーブのサイズ `0x48BB0`

## ユーザー報告

- 「体型・身長は確定」と報告。エディタからの体型・身長の書き込みの反映を確認済みとして扱う ✅ [U]。
- 性別を変えた後、UIの見た目関連が「見た目の候補領域を一意に特定できません」になった。
- `sample/S4-DATA_04 copy 5` が性別変更後のセーブ。変更した方向、ゲーム内確認に使った体型・身長の個別の値や出力ファイル名は未報告。

## サンプル

| ファイル | 状態 |
|---|---|
| `sample/S4-DATA_04 copy 4` | 身長低い・体型細め・肌色褐色 |
| `sample/S4-DATA_04 copy 5` | ユーザー報告の性別変更後 |

全体の差分は125 B。見た目の周辺では複数の値が同時に変わっている。

## 探索に関わる差分

| 位置 | copy 4 → copy 5 | 意味・解釈 |
|---|---|---|
| `0x3AAD4` u16 LE | `0xFFFF` → `0x00EE` | 容姿の関連IDの候補 ❓ |
| `0x3AAD6` u16 LE | `0x00F5` → `0xFFFF` | 容姿の関連IDの候補 ❓ |
| `0x3AAD8` | 1 → 0 | 肌色の候補 🔶 |
| `0x3AADC` | 1 → 0 | 性別に関わる値の候補 🔶。性別名と値の対応は未確認 |
| `0x3AADD` | 1 → 0 | 体型 ✅ |
| `0x3AAE0` float32 LE | 144.0 → 175.0 | 身長 ✅。175.0の選択肢名は未確認 |
| `0x46338` float32 LE | 160.0 → 175.0 | 関連領域の身長風の値 ❓ |
| `0x4633C` | 2 → 0 | 関連値 ❓ |

`0x3AADA` のu16 LEは3、`0x3AADE` の2 Bは0のまま。

## 原因と対応

- 位置探索で `0x3AAD6` 相当のIDを `0x00F5`、`0x3AADC` 相当の値を1に限定していた。また関連領域ではfloat32の160.0を固定の目印にしていた。性別変更後の観測値はこれらの条件から外れる。
- 探索対象のIDに `0x00EE`・`0xFFFF`、性別側の候補値に0を加えた。関連領域のfloat32は固定値ではなく、有限の100〜250という暫定範囲で検証する（🔶 U-18）。候補の一意性、サイズ、領域順の検証は継続する。
- 条件を広げると、`0x3AC6C`・`0x3DB88` にも先頭16 Bが一致する見た目の写しが見つかる。編集対象の `0x3AAD4` には先頭+`0x154` に `FF FF 00 00`、先頭+`0x158` に64 BのUTF-16LEの名前欄が続く。写しにはこの並びがないため、区切りと名前の終端・埋め込みの検証を加えて区別する（🔶）。
- 性別変更後の並びを合成したテストで、読み取りと体型・身長の個別書き込み、全バイト一致の書き戻しを確認する。テストではsample/を読まない。

## 残る確認

- 性別そのものの保存幅、値と性別名の対応、肌色・関連値の書き込み反映。

## 固定位置への変更（同日）

ユーザー判断で位置探索を廃止し、肌色 `0x3AAD8`、体型 `0x3AADD`、身長 `0x3AAE0`、関連値 `0x4633C` を固定位置として使う。性別変更後もこれらの位置は同じだった。周辺のID・名前・見た目の写しは編集可否の条件にしない。サイズ・境界・身長の有限値100〜250と書き込み値の範囲を検証する。肌色・関連値の意味と反映の確度は変更しない。全レイアウトで固定位置が使えるかはU-1に残す。
