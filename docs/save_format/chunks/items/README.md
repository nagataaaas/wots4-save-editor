# アイテム

箪笥・手持ち（道具）・貴重品（重要品）のアイテム枠。どれも 1枠 8 B の同じ構造で、3つの配列が並ぶ。

## 範囲

| 項目 | 値 | 確度 |
|---|---|---|
| 開始 | `0x0058C0` | ✅ |
| 終了（含む） | `0x005BDF` | ✅ |
| サイズ | 8 B × 100件（箪笥80＋手持ち10＋貴重品10） | ✅ |
| 位置の求め方 | 固定（U-1）。アンカー探索の目安：8 B 単位で、ID が既知の一覧にあり、個数が 999 以下 | ✅位置 ／ 🔶探索 |
| 妥当性検証 | 全枠で ID が既知の一覧か `0xFFFF`、空き枠は個数 0 | 🔶 |

```text
箪笥[n]   = 0x58C0 + n * 8   （n = 0〜79）
手持ち[n] = 0x5B40 + n * 8   （n = 0〜9）
貴重品[n] = 0x5B90 + n * 8   （n = 0〜9）
```

## 構造

| 位置 | 幅 | 型 | 内容 | 値 | 確度 |
|---|---|---|---|---|---|
| `+0x00` | 2 B | u16 | アイテムID | 箪笥・手持ち：[アイテム](../../datatable/item/item.csv)、貴重品：[貴重品](../../datatable/item/valuable.csv)。`0xFFFF`＝空き | ✅ |
| `+0x02` | 2 B | u16 | 個数 | 空きは 0 | ✅ |
| `+0x04` | 1 B | u8 | アイテムの種類。道具は `0x06`。手持ちでは `0x06` でないとゲームが落ちる | 箪笥・手持ち・貴重品とも `06`（[U] sample） | ✅値（手持ち） ／ 🟢意味・箪笥・貴重品 |
| `+0x05` | 3 B | — | 枠ごとに違う値。品・店から決まらない。🔶 取得時刻か乱数 | 0 でもよい | ❓ |

- 空き枠は `FF FF 00 00 00 00 00 00`
- 手持ちの1枠にまとめて持てる最大数は、アイテムごとに決まっている 🟢（[item.csv](../../datatable/item/item.csv) の `max_stack`）。
  ほとんどは 1 で、店で買った砥石2個が別々の2枠に個数 1 で入っていた（[U]）のと合う。がらくた 10、お宝 5、鉄 999、コイン 9999、エサ 10
- 箪笥の枠は最大数を超えて入る（刀油×13 など [U] sample）
- 道具として手に入らない ID がある 🟢（item.csv の `obtain`：1＝その場で使う料理・宿、2＝手に入る経路がない）
- 貴重品と通常アイテムは同じ ID 空間と推定 🔶（[datatable](../../datatable/README.md)）

## 編集時の注意

- 手持ち・箪笥の空き枠にアイテムを入れるときは、+0x04〜+0x07 に `06 00 00 00` を書く。手持ちで +0x04 が `06` でないと、店の売却一覧を開くときに落ちる。
  箪笥に書いた枠をゲームで読めるかは要ゲーム内確認
- 個数は、手持ちは最大数（`max_stack`）まで、箪笥は 999（🔶）まで。上級者モードでは u16 の上限まで書ける
- `obtain` が 1・2 の ID は、上級者モードでだけ選べる
- チップ・木札（`0x2D`／`0x2E`）は選択肢に出さない。書くとゲーム内でセーブできなくなる。すでに入っている枠は、ほかの ID への変更だけを許す
- 重要品の枠に任意の ID を書くのは ID 調査モード（上級者モード）だけ。`0x2D`／`0x2E` はこのモードでも拒否する
- 拷問部屋の鍵（`0xED`）・謎の鍵（`0xEE`）は ID が 🟢（U-14）。通常の選択肢に出すが、ゲーム内で未確認なので書くと警告を出す
