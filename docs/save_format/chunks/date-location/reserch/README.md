# 日付の段階・時間帯・現在地 に関する調査

- `./2026-10-05_time-of-day.md`: シナリオ差分で `0x0010`・`0x0012`・`0x0014` を見つけ、書き換えでゲーム内の反映を確かめた。日数は `0x0010` ではなく `0x0BD8` と判明
- `./2026-10-05_day4.md`: 4日目以降の差分。`0x0010` は 400 で止まり、時間帯は `0x0014`、日数は `0x0BD8` だけが進む
- 現在地 `0x0013` の値の一覧は [W-PC] による。u8 であることは [U] 2026-10-04 の書き換えで確認した（U-7。個別の調査ファイルはない）
- `./2026-10-07_public-order.md`: 手元のセーブの `0x0015` が 0〜99 に収まることを確かめ、治安の候補とした。2026-10-08 に書き換えがゲーム内の治安に反映されることを確かめ、治安と確定した
- `./2026-10-08_day5-slot.md`: 5日目の昼 → 夕の差分。4日目以降の時間帯は `0x0014` だけで表し、`0x0BDC` 以降は関係しないと確かめた。日数・時間帯・段階の役割を整理した
- `./2026-10-08_new-cycle.md`: 周回の途中のセーブで新しい周回を始める書き込みを確かめた。`0x0010` だけでは序章のイベントが始まらず、船上の侍を 00 にすると始まった。エンディング後のセーブから、周回ごとに初期化される範囲を推定した（🔶）。その範囲をまとめて書くと新しい周回として遊べた ✅
- `0x0010`＝0 が新しい周回の開始前の状態であることは [difficulty](../../difficulty/reserch/2026-10-08_difficulty.md) の調査で確かめた
