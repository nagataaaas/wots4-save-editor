# 周回の途中のセーブを新しい周回の始めに戻す

- 日付：2026-10-08
- 目的：周回の途中のセーブを、エンディング後と同じように「続きから」で新しい周回を始められる状態にする
- 環境：Steam版、0x48BB0

## サンプル

| ファイル | 操作 | ベースからの差分 |
|---|---|---|
| 実セーブ A | エンディング後（周回の開始前）。難易度 超難しい | — |
| 実セーブ B | A をロードし、主人公の設定を終えて大通りでセーブ | 424 B |

## 差分

A のイベントの状態 A（`0x36A8`〜`0x374D`、166 件）は `00` が 71 件、`FF` が 95 件。
`FF` は通し番号 2・10・14・16・19・25・32・53〜56・59〜61・64〜69・74・76・80・83・93〜96・99〜165。

A → B で変わったイベントの状態は、船上の侍（通し番号 0、`0x36A8`）の `00` → `04` だけ。
`0x3756`・`0x3762`〜`0x3763`・`0x378D`・`0x37C1`〜`0x37C2` も 0 → 1・2 に変わった。
エンディング後のセーブの時点で、イベントの状態とフラグはすでに周回の始めの値になっている。

## 書き込みの確認

- B の `0x0010` だけを 0 にすると、「続きから」で難易度と主人公の設定に進んだ。そのまま始めると、序章のイベントではなく、セーブした場所から始まった ✅ [U]
- さらにイベントの状態で船上の侍を未到達にすると、序章のイベントが始まった ✅ [U]

## 初期化の範囲の推定

A で周回中の値とみられる範囲の値：

- [stats](../../stats/README.md)：`0x0B90`（周回中のプレイ時間）・`0x0BC0`・`0x0BC8`（周回中の斬殺数）・`0x0BD0`・`0x0BD8`（経過日数）が 0。累計の `0x0B94`・`0x0BCC` は 0 ではない
- [kill-counts](../../kill-counts/README.md)：周回中の表 `0x0C84`〜`0x1C23` がすべて 0
- [scenario-flags](../../scenario-flags/README.md)：`0x374E`〜`0x3837` のうち 0 でないのは施設 `0x375D`〜`0x375F`（1）と堂島の職 `0x3799`（1）だけ
- [hint](../../hint/README.md)：`0x3900`＝`FFFF`

周回の途中のセーブ2件（B と、5日目夕のセーブ）にこの範囲を A の値で書くと、A との違いは時間で進む値・[memory-garbage](../../memory-garbage/README.md)・[belt-copy](../../belt-copy/README.md)・治安 `0x0015`・`0x0133`・難易度だけになった。

エディタの「新しい周回を始める」で周回の途中のセーブにこの範囲を書くと、新しい周回として遊べた ✅ [U] 2026-10-08。

## 結論

- 2つの書き込みを用意した（[U] 2026-10-08 のユーザー判断）
  - 難易度と主人公設定を行えるようにする：`0x0010` だけを 0 にする ✅
  - 新しい周回を始める：上の範囲を A の値にそろえる。まとめて書いて遊べることは ✅。個々の値は `0x0010`＝0、船上の侍＝00 が ✅、ほかは 🔶。現在地も `27` にする（必要かは ❓）
- 施設（周回をまたぐ 🔶）と堂島の職 `0x3799`（❓）は変えない
- エンディングで初期化される範囲は、同じ周回のエンディングの直前と直後のセーブを比べれば確かめられる（未調査）
