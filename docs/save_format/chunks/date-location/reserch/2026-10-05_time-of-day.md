# 時間帯と日数の差分

- 日付：2026-10-05
- 目的：イベントの進行と時間帯の変化で動くバイトを特定し、書き換えで確かめる
- 環境：Steam版、ファイルサイズ 0x48BB0

時間で進む値（`0x0B90`・`0x0B94`・`0x0BC0`・`0x0BC4`・`0x35AC`・帯刀の +0x86/+0x8A）、`0x363C`〜 の乱数領域、`0x1A68A`〜 のコピー領域は除いた。

## 差分

| 位置 | 変化 | 解釈 | 確度 |
|---|---|---|---|
| `0x0013` u8 | copy → copy 2：`0D` → `01`、copy 2 → copy 3：`01` → `06` | 現在地：大通り → 港 → 町 | ✅ |
| `0x0012` u8 | copy 3 → copy 4：`00` → `0A`、copy 4 → copy 5：10 → 0 | 時間帯を進める保留量。イベント完了で 10 が入り、エリア移動で `0x0010` へ足されて 0 に戻る | 🔶 |
| `0x0010` u16 | copy 4 → copy 5：100 → 110、04 copy 2 → copy 3：120 → 200 | 日×100＋時間帯×10 | 🔶 |
| `0x0014` u8 | copy 4 → copy 5：0 → 1、04 copy 2 → copy 3：2 → 0 | 時間帯（0＝昼、1＝夕、2＝夜） | 🔶 |
| `0x0BC0` float | copy 2 → copy 3：+777.9（実時間 +778 秒）、copy 3 → copy 4：+3,360.9（実時間 +208 秒） | 完了時だけ大きく進んだ。意味は不明 | ❓ |
| `0x0BD8` u32 | 2日目に入った3つのセーブ（04 copy 3・03 copy 6・04 copy 5）だけ 0 → 1、ほかの11件は 0 | 経過日数（1日目＝0） | 🔶 |

`0x0010`・`0x0014` と各セーブのゲーム内の時間帯：

| セーブ | `0x0010` | `0x0014` | ゲーム内の時間帯 |
|---|---|---|---|
| 03 copy〜copy 4 | 100 | 0 | 1日目昼（[U]） |
| 03 copy 5 | 110 | 1 | 1日目夕（[U]） |
| 04 copy・copy 2 | 120 | 2 | 🔶 1日目夜（未確認） |
| 04 copy 3 | 200 | 0 | 2日目朝（[U]） |
| `S4-DATA_01` | 120 | 2 | 🔶 1日目夜（墓場。未確認） |
| `S4-DATA_04` | 110 | 1 | 🔶 1日目夕（未確認。`0x0015` が `3E` で、ほかのセーブは 0） |

## 書き込みの確認

| 項目 | 書き換え | ゲーム内の表示 | 判定 |
|---|---|---|---|
| `0x0012` | 10 → 0（03 copy 4） | エリア移動しても時間帯が進まない | ✅ |
| `0x0010`・`0x0014` | 時間帯の部分を変更（両方を同時に書いた） | 反映された。どちらのバイトが効いたかは ❓ | ✅ |
| `0x0010` の日の部分だけ | 1日目 → 2日目 | 変わらなかった。日数は別の場所にある | ✅（否定） |
| `0x0BD8`（＋`0x0010`・`0x0014`） | 03 copy 5（1日目夕）→ 2日目 | 2日目になった。2日目昼までに済ませていないイベントは、すべて自動的に失敗になった | ✅ |

## 結論

- `0x0010`（段階）・`0x0012`（保留量）・`0x0014`（時間帯）を ../README.md に追加した
- 日数は `0x0BD8` u32（経過日数、1日目＝0）。エディタは日数を書くとき `0x0BD8`・`0x0010`・`0x0014` を一緒に書く。`0x0BD8` だけで足りるかは ❓
- 日を進めると、ゲームはロード時に過ぎた時間帯の未処理イベントを失敗にする
