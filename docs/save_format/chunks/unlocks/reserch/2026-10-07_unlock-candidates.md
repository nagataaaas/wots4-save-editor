## 手元のセーブの値

実セーブ（スロット 00〜04、`bak` の4件）を読んだ。

| 位置 | 値 |
|---|---|
| `0x3902`〜`0x399F` | 進行の早い2件は ID 0・152 だけ 1。なりわい4件のクリア後は 0・152・154〜157 が 1 |
| `0x3AB60`〜`0x3AB9B` | `0x3AB79` が `40`（早い2件）か `C0`、`0x3AB7A` が `00` か `03`。ほかは 0 |
| `0x3AB9C`〜`0x3AC05` | 早い順に {40:1} → {9:1, 13:1, 40:1, 72:1} → {0:2, 1:1, 2:1, 9:1, 13:1, 40:1, 67:1, 72:1}。スロット 00（2026-10-06）だけ全部 0 |
| `0x3AC06`〜`0x3AC27` | 全部 0 |
| `0x3AC28`〜 | `FF FF 00 00` に続いて UTF-16 の「名無し侍」 |

- `0x3AB9C`〜 の値は進行とともに増えていて、値は 0・1・2 だけ。106件で 0 の並びに切り替わる
- 番号を特典の一覧の順に読むと、0 武器箪笥 壱（条件なし）＝2 は合うが、9 肌の色（緑）・13 髪の色（ピンク）・40 百合の顔は条件を満たしていない。
  「条件なし」の 4・6・17・18・25・26・84 は 0 のまま。並びが一覧と違うか、別の表である可能性が残る

## 書き込みの確認

2026-10-07、ユーザーがエディタでライフルの免許（番号101）を取得済みの2に変更し、ゲーム内で取得できるようになったと報告した ✅ [U]。対象バイトは探索した先頭+101（確認した配置では `0x4337D`）。変更前の値と書き出したファイル名は未報告。0・1への変更の効果、ほかの特典への書き込みは未確認。

## ゲーム内表示との照合（2026-10-07）

`sample/S4-DATA_04 copy` をロードしたときの報告：武器箪笥 壱〜参は取得済み・四は非表示、難易度は超難しいまで取得済み、肌の色は色黒・赤が表示中で未取得、髪の色は赤・黄緑・ピンクが表示中で未取得。それ以外の肌・髪の色は非表示。

| 範囲 | バイト列 | ゲーム内表示との対応 |
|---|---|---|
| `0x43318`〜`0x4331B` | `02 02 02 00` | 武器箪笥 壱〜四 ✅ [U] |
| `0x4331C`〜`0x4331D` | `02 02` | 難易度 難しい・超難しい ✅ [U] |
| `0x4331E`〜`0x43322` | `01 01 00 00 00` | 肌の色 色黒・赤・白・緑・青 ✅ [U] |
| `0x43323`〜`0x43327` | `01 01 01 00 00` | 髪の色 赤・黄緑・ピンク・藍・紫 ✅ [U] |

`0x43318`〜`0x43381` は106件の表に一致する。直前16 B、直後22 B は0で、続く16 B は小さな u16 値の列。`0x3AB9C`〜 の非ゼロは8件だけで、今回確認された表示中・取得済みの件数に足りず、先頭の状態も一致しない。この範囲は特典解除の状態から外した。

## 結論

- 特典解除の状態は `0x43318`〜`0x43381` と判定。先頭16件の表示と101への2の書き込みは ✅ [U]、ほかは 🔶 U-17
- 容姿のビット列の範囲の候補を U-16 にした

## 固定位置への変更（同日）

ユーザー判断で状態列の位置探索を廃止し、`0x43318 + 番号` を固定位置として使う。ファイルサイズ0x48BB0、106 Bの境界、全要素0〜2を検証する。直前・直後の区切りと後続の数値列は編集可否の条件にしない。未確認の番号の対応と書き込み反映はU-17に残す。
